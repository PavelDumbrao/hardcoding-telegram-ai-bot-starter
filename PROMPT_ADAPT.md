### ПРАВИЛА РАБОТЫ

1. Прочитай `README.md`, `LESSON_01.md`, `ARCHITECTURE.md`, `AGENTS.md` и исходники. Проверь `git status`, текущую ветку и существующие тесты. Не изменяй соседние проекты.
2. Используй существующие `bot/routers`, `bot/services/ai.py`, `bot/db.py` и настройки. **Не переписывай проект с нуля.**
3. Сформулируй сценарий в трёх предложениях: кто приходит, что делает, какой результат получает.
4. Сам сделай минимально необходимые изменения: приветствие, роль ИИ, главное действие и, если требуется, одну кнопку. Не добавляй технологии «на вырост».
5. Сохрани `/start`, `/help`, `/reset`, ответы только в личных чатах, память SQLite и обработку ошибок.
6. Используй существующий OpenAI-compatible интерфейс: `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `SYSTEM_PROMPT`. Не привязывай бизнес-логику к поставщику.
7. Не спрашивай меня, какие библиотеки или команды использовать. Если отсутствует **важная бизнес-информация**, задай только один вопрос о пользователе или продукте.
8. Установи зависимости при необходимости, добавь тесты к новой логике и выполни `pytest -q`, `ruff check .`, `python -m compileall -q bot`. Ошибки устраняй самостоятельно.
9. Никогда не проси отправлять ключи и BOT_TOKEN в обычный чат. Храни секреты только локально в `.env`; не добавляй их в коммиты, PR или журналы.
10. GitHub — источник правды. Работай только в моей копии проекта; при значимых изменениях используй отдельную ветку, commit, push и PR, если есть доступ. **Не делай merge в main без моего разрешения.**
11. Не объявляй живой Telegram E2E успешно пройденным, пока не проверишь своего тестового бота с реальным токеном и доступным AI-провайдером. Не запускай второй экземпляр polling с тем же токеном. Без ключей напиши **E2E НЕ ПРОВЕРЕН**.
12. В конце отчитайся: **Сделано → Проверено → Не проверено → Как запустить → Одно следующее улучшение**.

### ОГРАНИЧЕНИЯ

Для первого запуска оставь **Python 3.12, aiogram 3, SQLite, long polling и OpenAI-compatible Chat Completions**. Не добавляй FastAPI, Docker, Redis, PostgreSQL, LangChain или инструменты агента, если они не нужны основной функции. Не собирай данные из групп.

Начинай с чтения проекта и существующих проверок. После этого реализуй работающий сценарий.
