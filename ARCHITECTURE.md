# 🗺 Архитектура: простое ядро для дальнейшего роста

```text
Пользователь в Telegram (личный чат)
                |
                v
          aiogram 3 (polling)
                |
    +-----------+-------------+
    |                         |
routers/start.py         routers/common.py
/start /help /reset      меню / сообщения
                               |
                      +--------+-------+
                      |                |
                      v                v
                services/ai.py      db.py / SQLite
                OpenAI-compatible   история + события
                /chat/completions   отдельные для каждого ID
                      |
                      v
                  Ответ пользователю
```

| Файл | Назначение |
|---|---|
| `bot/main.py` | Запуск и подключение |
| `bot/config.py` | Настройки из `.env` |
| `bot/routers/start.py` | Команды и приветствие |
| `bot/routers/common.py` | Кнопки, вызов ИИ и обработка ошибок |
| `bot/services/ai.py` | Провайдер и запрос к LLM |
| `bot/db.py` | SQLite, память и аналитика |
| `tests/` | Офлайн-проверки |

## Лестница развития

- **Уровень 1 — сейчас:** диалог с ИИ, ограниченная память, `/reset`, локальный запуск.
- **Уровень 2 — продукт:** основной сценарий, FSM/анкета, событие успешного действия.
- **Уровень 3 — агент:** отдельный слой разрешённых инструментов (tool calling), валидация аргументов, подтверждения опасных действий, логи вызовов. Никакого произвольного shell-доступа модели.
- **Уровень 4 — система:** CRM, база знаний/RAG, права доступа, очередь, мониторинг, сервисный деплой — только по реальной потребности.

`AI_HISTORY_LIMIT` ограничивает **число реплик**, а не токенов модели. Бот обрабатывает **только личные чаты**. Long polling требует **одного процесса на BOT_TOKEN**; для бесперебойной работы нужен хостинг. OpenAI-compatible не гарантирует одинаковые возможности всех провайдеров.
