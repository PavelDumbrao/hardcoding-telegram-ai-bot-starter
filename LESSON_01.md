# Урок 01. Собери собственного Telegram AI-бота

**Результат:** у тебя есть собственная GitHub-копия кода, а Telegram-бот отвечает с помощью выбранной AI-модели. Мы управляем разработкой через промпт, а не переписываем библиотеку с нуля.

Переходи к следующему блоку **только после его проверки**.

## Блок 1 — Создай свой репозиторий

**Задание.** Забери исходный проект себе.

**Решение.** Открой публичный репозиторий Hardcoding PRO. Нажми `Use this template` → `Create a new repository` → выбери своё имя, например `my-first-telegram-ai-bot`. При желании поставь Private. Открой свою копию в Codex, Claude Code или ZCode. Если работаешь с терминалом, клонируй **свой** репозиторий через `git clone <свой_URL>`.

**Проверь себя.** В адресной строке GitHub указан **твой аккаунт**; в проекте видны `README.md`, `LESSON_01.md`, `bot/`, `.env.example`.

**Готово, если:** твоя копия существует, общий учебный исходник не изменён.

## Блок 2 — Установи и проверь основу

**Задание.** Подготовь Python 3.12 и проверь код без ключей.

**Решение.** Следуй командам своей ОС из README. На Mac/Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest -q
ruff check .
python -m compileall -q bot
```

На Windows используй `.venv\Scripts\python.exe -m pytest -q`, а установку — по README. Агент-кодер может выполнить всё сам.

**Проверь себя.** Все тесты успешно завершились; `ruff` пишет `All checks passed`; компиляция не выдаёт ошибок.

**Готово, если:** код проверен и зависимости установлены, даже если ключей ещё нет.

## Блок 3 — Включи Telegram и ИИ

**Задание.** Создай своего бота и безопасно задай параметры ИИ.

**Решение.** Открой официальный [@BotFather](https://t.me/BotFather), отправь `/newbot`, выбери имя и уникальный username, заканчивающийся на `bot`. Скопируй `.env.example` в `.env` и **локально** заполни `BOT_TOKEN`, `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`. Используй действующие настройки **своего** провайдера.

**Проверь себя.** В `.env` все обязательные поля заполнены; `git status --short` не показывает файл `.env`. Не показывай ключи на демонстрации или в скриншотах.

**Готово, если:** токены хранятся только локально и не попали на GitHub.

## Блок 4 — Пройди живой тест в Telegram

**Задание.** Доказать, что бот отвечает на реальные сообщения.

**Решение.** Запусти `python -m bot.main` (Windows: `.venv\Scripts\python.exe -m bot.main`), оставь процесс работающим. Открой свой Telegram-бот и последовательно отправь:

1. `/start` → приветствие и меню;
2. `/help` → краткая инструкция;
3. `Придумай три названия кофейни` → три названия;
4. `Выбери самое короткое` → ответ с учётом контекста;
5. `/reset` → подтверждение очистки; новый вопрос не должен использовать старый контекст.

**Проверь себя.** Ответы видны **в твоём Telegram**; в консоли показано успешное подключение к API. Команды могут работать при неработающем AI, поэтому обязательно проверяй текстовый ответ от модели.

**Если не получилось.** `401` — ключ/права, `404` — модель/base URL, `getUpdates Conflict` — два polling-процесса, бот молчит — процесс или сеть. Для внешнего API может потребоваться оплаченный баланс.

**Готово, если:** успешны все 5 пунктов. Если ключей нет, честно пометь **E2E НЕ ПРОВЕРЕН** и не переходи к утверждению, что бот работает.

## Блок 5 — Адаптируй бота промптом

**Задание.** Сделай бота полезным конкретной аудитории.

**Решение.** Открой [PROMPT_ADAPT.md](PROMPT_ADAPT.md), скопируй промпт целиком кодинг-агенту и заполни описание продукта. Варианты: репетитор английского; консультант по услугам; помощник школы; тренажёр продаж; бот для FAQ (пока без RAG).

**Проверь себя.** Агент сохранил изменения в **твоей** GitHub-копии; офлайн-тесты снова прошли, а приветствие/основной сценарий реально изменились в Telegram. В GitHub нет `.env`.

**Готово, если:** пользователь решает одну понятную задачу, а у тебя есть рабочий проект и следующий шаг.

## План демонстрации для преподавателя

1. Покажи ученикам готового бота и маршрут из пяти блоков.
2. Покажи кнопки `Use this template` и папки репозитория.
3. Продемонстрируй безопасную настройку **без показа секретов**.
4. Пройди `/start` → вопрос → уточнение → `/reset`.
5. Вставь универсальный промпт, измени роль и повтори проверку.

**Важно:** демонстрационная программа может потребовать API-баланс. Локальный запуск не означает работу 24/7.
